# F22 飞机比赛工程交接文档

更新时间：2026-10-26  
交接对象：下一位负责 F22 飞机比赛调试、实飞和参赛准备的同学

## 1. 先看结论

本仓库当前的主项目是 F22 四轴飞机的悬停组比赛工程，不是轮式小车工程。仓库中没有发现独立的“小车”底盘、轮电机或小车控制入口；如果这里说的“小车”是对飞机机体的口头称呼，下面的“车体”均指这架 F22 飞机及其飞控板。如果实际要交接另一台轮式小车，需要另找工程目录，不能直接使用本目录的控制代码。

当前目标是：飞机放在比赛地图红色中心区，无线一键起飞，自动保持 20～100 cm 高度和位置，保持至少 5 s，再无线降落回中心附近。巡航组尚未实现，不能把现在的工程当作巡航任务程序。

当前项目处于“传感器和控制闭环已接通，进入系留实飞调参前后，但还没有比赛验收”的阶段。已经有较完整的主机回归、固件构建、部分 SWD 烧录读回和传感器启动证据；尚未证明飞机能安全离地、稳定悬停、控制横向漂移或稳定落回中心。任何文档中出现 `state=3`、ToF 有效、PWM 有输出，都不能单独当作悬停通过。

## 3. 比赛要求和工程目标的区别

规则来源是 `docs/references/比赛实施方案_2026.7.pdf` 第 9～13 页。当前仓库据此采用悬停组目标：

| 项目 | 比赛要求 | 工程当前采用的验收目标 |
|---|---|---|
| 机型 | 4 轴或 6 轴 | 一架四轴，虚拟顺序为 FL=M2、FR=M1、RR=M3、RL=M6 |
| 起飞 | 在红色中心区，无线一键起飞 | F2 请求起飞；必须是一次新的、有效的起飞命令 |
| 飞行控制 | 起飞后自主控制，只允许起降遥控 | 不加入方向和油门遥控 |
| 悬停高度 | 20～100 cm | 首个稳定目标约 40 cm；低空调参 profile 目标 12 cm；普通 profile 目标 20 cm |
| 稳定时间 | 至少 5 s，不掉落、不跑飞 | 首轮实飞建议稳定记录至少 6 s，再做正式 5 s 判定 |
| 降落 | 一键降落 | 当前映射为 F3 受控降落，F4 立即停机；不要自行只改一端 |
| 高度 | 不超过 1 m | 系留测试和代码保护必须保留高度边界与故障处置 |
| 得分 | 中心圈 500 分，外圈逐环减少；机身中心标记可加分 | 光流只能帮助相对保持，不能识别红圈；最终落点必须人工记录和核对 |
| 安全 | 约 1.5 m 牵引绳可靠连接重物，观众距地图至少 2 m | 所有带桨试飞先系留、清场、急停可触达 |
| 地图/器材 | 自带约 1.6 m×2.4 m 哑光地图；电池、动力和控制器要合规 | 最后必须在实际比赛地图、光照和电池配置下复验 |

规则没有规定“90% PWM”“3 秒离地超时”“8 cm 交接”“40 cm 目标”等数值。这些是开发保护或调试参数，不能写成比赛条款。规则文件也可能后续更新，报名和参赛前必须重新核对正式通知。

## 4. 硬件和控制链

硬件主线是 STM32F103RC 飞控板、F22 原厂动力/控制器、M1/M2/M3/M6 四路电机、TLE100/E49 无线链路、IMU、PMW3901 光流和同板 ToF 模块。光流和 ToF 通过 I²C/SPI 组合模块接入，传感器窗口朝地，箭头暂按机头方向安装；安装轴向和比例仍不能视为完全标定。

代码控制链为：

```text
TLE100 -> USART1/E49 接收 -> 命令门控 -> ClosedLoop_Step
IMU --------------------------^       |
ToF -> 高度观测/垂直环 --------------  |
PMW3901 -> 光流辅助/试验刹车 ---------  |
姿态、角速度、高度、光流 -> 混控 -> M1/M2/M3/M6 PWM
                                    -> JP13 遥测/日志
```

主要按键约定：

| 按键 | 作用 | 注意 |
|---|---|---|
| F1 | 待机/IMU 校准相关操作 | 不能代替真正的起飞许可 |
| F2 | 起飞 | 仅在待机、姿态/高度条件满足时接受 |
| F3 | 当前主线为受控降落 | 连续包不能把降落计时重新变成新的起飞 |
| F4 | 立即清零/急停并清状态 | 需要重新 F2 才能再次起飞；历史上曾有过 F3/F4 对调候选，已撤回 |

实际烧录前必须同时核对遥控器发送端和飞控接收端的键映射。不能只修改接收端，也不能因为日志出现 `KEY ... allowed=1` 就认定电机已经启动。

## 5. 控制代码现在做了什么

### 5.1 启动和故障保护

- 上电默认 PWM 全零，不自动解锁；需要新的 F2。
- IMU 启动时先做静止校准，要求连续合格样本；静止校准不能识别所有持续线加速度。
- 传感器缺失、姿态无效、倾角过大、时间步长异常、输出故障、遥控失联等会进入故障或降落路径。
- I²C2 启动清总线已经加入，解决过调试复位后 BUSY 导致 IMU/ToF 不可用的问题。
- ToF 原始 5～39 mm 属于近地盲区策略，不等于有效高度；有效高度门限约 40 mm。
- 失联处理有“已获得高度”和“仍在近地起飞盲区”两条路径。盲区没有新鲜近地证据时不会假设飞机已经落地，而是故障停机。

### 5.2 姿态和混控

IMU 姿态/角速度闭环在整个飞行过程中工作。当前配置仍以 `src/config.h` 中未验收标志为准：`IMU_MOUNT_VERIFIED=0`、`FLOW_CALIBRATED=0`。`closed_loop_config.h` 中只在明确的姿态/系留试验 profile 放行相应轴向；普通生产 profile 仍受门控。

电机虚拟顺序为 M2/M1/M3/M6，`Aircraft1_MapMotors()` 再映射到板端。M1/M3 与 M2/M6 的左右、前后、旋向差分必须以拆桨方向检查和带桨系留实测分别确认；不能用旧教学固件的 PWM 极性。当前代码采用高有效 PWM，`CCR=0` 停止，未选通道 GPIO 拉低。

### 5.3 高度和降落

ToF 有效时，观测器给出高度和垂直速度，垂直 PI 围绕起飞时捕获的混控均值工作。这个均值只是起飞参考，不是已经标定的悬停油门。降落阶段有公共推力下降限速和近地末段递减；平滑的 PWM 曲线也不能证明真实软着陆。

### 5.4 光流

光流代码已经支持相对 XY 位置保持和速度内环，也有 `CL_FLOW_BRAKE_ONLY` 低增益刹车试验。当前 `FLOW_CALIBRATED=0`、`CL_FLOW_AXES_VERIFIED=0`，配置中的 `forward=+dy/right=+dx` 和 `0.002131946 rad/count` 仍是试验性名义值。历史采集受到手持倾斜、绳子拉紧、平移距离不确定等影响，不能直接写入正式标定。光流 ID、通信和数据读取正常，不等于轴向、比例、旋转补偿和横向控制已验收。

3. 只用当前源码构建并记录版本：

   ```bash

   PATH=/home/czy/.platformio/penv/bin:$PATH bash scripts/check_closed_loop.sh
   ```

4. 通过 JP11 读取当前 Flash，保存 256 KiB 备份；不要先烧录。接 JP13/USB 后记录启动 marker、`state`、`fault`、`link`、`ready`、IMU/ToF/flow 状态和四路 PWM。板上实际固件以这些记录为准，不以文件名猜测。
5. 检查遥控器 `remote/tle100` 的实际发送版本和键位；确认 F2/F3/F4 是成对协议，确认 F4 能在接收端立即清零。
6. 如果启动时 `state=0/fault=0/PWM=0` 但 `link=0`，这是待机且没有遥控链路，不是“电机锁死故障”；先恢复通信，再做任何 F2 测试。

## 8. 推荐的后续执行顺序

### 阶段 A：硬件和安全复核

- 拆桨核对 M1/M2/M3/M6 物理位置、旋向、PWM 极性和停止电平。
- 单独测每个电机端、驱动栅极和电池供电；不要在不清楚共地和电源路径时同时接 USB 与动力电池。
- 检查原厂动力和受保护电池是否符合比赛要求；更换过的板、MOS、稳压器或机架都要重新记录。
- 验收条件：F4/断链/看门狗能让四路 PWM 归零；拆桨方向表、接线照片、测量值和固件哈希进入 `docs/validation/`。

### 阶段 B：先只调姿态，不开光流

- 使用 IMU + ToF 的低空系留 profile，保持光流控制关闭；高度可以先用 12 cm 低空目标，逐步升到 20～40 cm。
- 先处理持续左/右、前/后和偏航的机械 trim，再调 rate PID；每轮只改 `closed_loop_tuning.h` 一个参数，改动 0.003～0.005 duty，保存前后日志。
- 不要用碰撞、绳子拉紧或已经触地后的角速度数据调参。
- 验收条件：可重复起飞，姿态不持续发散，不触发 fault，不碰绳/架，至少连续记录 6 s；再重复三轮。

### 阶段 C：处理 ToF 近地和降落

- 分别记录桌面盲区、垫高、离地、下降和落地的原始距离、状态、样本年龄、融合高度和 `vz`。
- 明确“仍在地面”“已离地”“近地着陆”三种状态，不能用单个 0～4 mm 或旧融合高度代替新鲜证据。
- 在系留状态验证 F3 受控下降、F4 急停、失联降落和重复命令；异常时优先保护，不为了连续飞行而放宽故障门槛。
- 验收条件：每条路径都有原始日志、预期状态转换和四路 PWM 结果。

### 阶段 D：独立完成光流标定，再开横向控制

- 使用电机锁止的 `contest_flow_calibration_jp13`，固定机体水平，在已知纹理上做已知距离的前后、左右平移；不要手持倾斜代替平移。
- 用可控转轴单独测旋转补偿；先验证符号，再拟合比例，最后用 holdout 数据复验。
- 只有两轴、比例、旋转补偿和断线/恢复都通过，才把标定写入 `src/config.h` 并将 `FLOW_CALIBRATED`/轴向许可改为 1。任何 provisional profile 必须继续标注为试验版。
- 验收条件：前后左右方向和距离误差在预先写明的门限内，重复采集结果一致，证据和脚本可复现。

### 阶段 E：整机系留、落点和比赛演练

- 把姿态/高度和光流分阶段合并；每次只引入一个新闭环。
- 先系留短飞，再逐渐增加高度和时间；全过程保留 F4 急停、操作员、视频和完整遥测。
- 在比赛地图同材质和光照下做起飞、6 s 悬停、F3 降落、中心落点和高度限制演练。
- 最终提交前固定一份“比赛镜像”：源码 commit、环境名、BIN、SHA256、遥控器 HEX、启动日志和现场检查表全部对应同一版本。

## 9. 不要踩的坑

- 不要把 `archive/`、教学工程或旧 `firmware/*.bin` 直接烧录；先核对环境和源码。
- 不要把 `contest_hover` 的无动力构建、主机测试、寄存器替身或 `state=3` 写成真实飞行验收。
- 不要在 `FLOW_CALIBRATED=0` 时把光流数据当作定点已经可靠；`present=1` 只表示设备识别。
- 不要因为 PWM 达到 900‰/1000‰ 就认定推力或悬停油门已标定。
- 不要在带桨、未系留、未确认 F4 的情况下修改多个 PID、刷多个镜像或进行连续起飞。
- 不要仅修改接收端按键映射；遥控器发送端、接收桥和控制器状态机必须一起验证。
- 不要用绳子拉紧后的旋转、碰撞后的倾角或触地后的故障数据调横滚/偏航增益。

## 10. 建议的每轮记录格式

每次修改或实测都新增一个日期目录，例如 `docs/validation/2026-10-26-attitude-trial/`，至少保存：

```text
manifest.json          # 环境、源码版本、BIN、SHA256、是否烧录/实飞
command.log             # 实际命令和退出码
serial.raw.log          # 原始串口，不只保存整理后的截图
analysis.json           # 结论、异常、下一步
photos/                 # 接线、机架、桨叶和地图（如有）
```

记录必须明确区分：`built`、`flashed`、`readback verified`、`boot verified`、`motor tested`、`tethered flight`、`competition accepted`。只有最后一项完成，才能写“比赛通过”。
