# 比赛准备：逐项实机验收

按顺序记录，每项分别写“通过 / 失败 / 待测”。构建成功不能替代实机验收。当前缺少地磁，气压与离地高度暂不作飞行反馈；光流、ToF尚无本轮验收证据。

## 1. 板健康和连续运行

只接USB，断开动力电池和电机。先检查是否迅速异常发热，再下载 `demo_selftest`，记录MCU UID、复位原因、Flash校验和完整日志。JP10的3.3V对GND用万用表测，软件VDDA只作参考。USB重枚举、程序重复重启和读数中断要单独记录。

QMC地址失败、气压失败与IMU测试分别判定；缺地磁不阻止IMU验证。供电、主芯片或程序运行有异常时，停止进入电机阶段。曾被认定损坏的板重新参加排查，不等于已经成为可用比赛板。

## 2. IMU和姿态

使用 `demo01_vofa`，115200 8N1 / JustFloat，启动前平放静止。CH0～2是加速度g，CH3～5是已减启动零偏的角速度°/s，CH7/8/14是roll/pitch/yaw角度，CH11是IMU通信有效位。CH14没有磁航向校正；CH19是气压相对高度，不是离地距离。

先保存至少60秒静置数据，记录有效帧数、间隔、加速度模长、各轴角速度均值/波动与姿态变化。六面检查逐面保持静止：每轴正反朝上时对应轴应接近±1g，另外两轴接近0；记录实际数值，再判断是否需要偏置/比例校准。最后分别前后倾、左右倾和水平旋转，记录物理方向、响应轴与正负号。尚未安装到飞机时，只能确认板坐标，不能宣布机体坐标通过。

遥测LED1合并IMU和气压状态，气压异常也可能使其报警；以CH11和原始IMU数据独立判断。目标值、控制输出的验证在姿态控制台架进行，本遥测环境不输出电机控制。

## 3. 遥控和失联

使用与TLE100发射端匹配的 `demo02_remote_framed`；独立UART4日志优先。无独立USB-TTL时可用 `demo02_remote_usb`（9600 8N1），但共享USART1的日志可能占用无线链路，不能据此验收无干扰射频稳定性。

先记录空闲心跳、有效包计数和错误计数，再依次按F1/F2/F3/F4，期望校准/起飞/降落/急停请求。每个动作由操作人确认，与日志时间对应。明确关闭遥控器后观察约300ms超时、重新上电恢复，各重复3次。这些固件只显示请求；未实际解锁、起飞或停机，不能作为电机失联保护验收。

## 4. 拆桨电机

确认桨已拆、动力供电符合手册、机架布局和操作者急停方式后，才使用独立 `demo03_motor_bench`。逐个记录M口与实物位置、旋向、PWM频率和零输出。检查按键门控、释放、超时、复位后的停止；之后在整机控制程序中单独验证无线失联确实使输出进入安全状态。

## 5. 姿态台架

固定且限制运动的台架上，确认安装坐标和真实混控；先角速度内环，再角度外环。记录目标、测量、误差、PID各项、饱和与每路混控值。先以零物理输出检查修正方向，再进行经过动力验收的受控实验。没有真实布局和恢复力矩证据时，不进入悬停。

## 6. 比赛流程与距离/光流

依据实施方案核对任务条件，分别记录起飞、稳定悬停、降落和异常退出验收。ToF到货后用尺测多个已知距离，验证有效状态、更新时效和丢测；光流验证前/右位移方向、尺度、倾斜和旋转补偿、光照与地面纹理。传感器模型和故障注入可先做，真实悬停通过必须有实际传感器及飞行证据。

每轮记录使用 [实验记录表](LAB_RECORD.md)，填写UID并保存原始日志，避免把不同板或不同固件的结果混在一起。
