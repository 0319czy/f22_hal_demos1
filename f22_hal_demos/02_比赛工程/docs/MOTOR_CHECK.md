仅用于拆桨验证电机编号、旋向、PWM和停止路径，不是飞行控制程序。先确认电机型号、M口和动力供电；[F22手册](references/F22_控制器手册_v2.0.pdf)第3.1节要求动力输入匹配电机额定电压，[DM22手册](references/DM22_电机组件手册.pdf)为额定3.7V、最高4.2V。桨全部拆下，确认实际停止电平和零占空比后才接合适动力。

## 独立环境

- `contest_motor_preview`：门控和遥控逻辑，不链接PWM驱动，应用值始终0；旋翼控制脚配置为GPIO低，符合原理图N沟道低侧MOS管的停止设置，仍须核对实物。
- `contest_motor_m1`：只启动M1 / PC6 / TIM3_CH1，真实PWM。M2～M4和M6/M7保持GPIO低，不切到未启动的定时器通道。目标通道先以CCR=0启动定时器，再切目标引脚到AF，减少路由切换时的不确定电平。M5不参与本测试，勿连接旋翼到M5。

```bash
pio run -e contest_motor_preview
pio run -e contest_motor_m1
pio run -e contest_motor_m2
pio run -e contest_motor_m3
pio run -e contest_motor_m4
```

M2/M3/M4环境使用相同门控，分别只启动PC7/TIM3_CH2、PC8/TIM3_CH3、PC9/TIM3_CH4。编译时编号与单路AF路由必须一致，不能把编译完成当作对应电机已运行。每一路完成位置记录及停止测试后，再下载下一路。

供电路径只读核对：USB经F1和D8_1接5V，与5V稳压器输出共网；JP2中心脚接BE_VIN，另两端分别接VIN和悬空。关闭该路径不等于整个实物系统已验证隔离。烧损原因及具体接线未明前，不再按此前接法上电，不向JP9/JP10/JP3/JP4接入未经核对的电源。

上述仅构建。真实PWM版本目前没有实机验收，不要在未知接线/电压下下载。默认环境仍为无动力输出的 `contest_hover`。下载电平、ROM GO启动按当前板实测方式处理，不能假定所有板一致。

## 操作与门控

USART1为9600 8N1，仅接收匹配TLE100的带心跳协议。有效链路不可缺；关遥控器或300ms没有新有效包时请求归零。先松开板上KEY1/KEY2，再长按KEY1满2秒才请求15%，最多运行3秒。松手、KEY2、遥控F4 STOP、接收错误/队列溢出均停止；停止后必须重新释放KEY1才能再次触发。无线F2不能直接启动电机。

F4请求锁存，不会被随后心跳覆盖。ISR字节保留实际到达时间，积压字节不能凭解析时间延长链路；错过超时轮询后出现的新连接也会退回释放等待。真实PWM环境启用独立看门狗，名义约0.5秒；LSI和实际断电/复位效果待测。

当前高有效PWM、1MHz计数、ARR66，周期67µs约14.9kHz；15%请求按既有HAL写CCR9，有效时间9/67约13.4%，不是精确15%。不转可能是启动摩擦，不能直接判坏或擅自提高油门。

## 观测与验收

导入 [motor_check.csv](../motor_check.csv)，9列全零模板。日志只从UART4 / JP14 PC10 TX输出，接3.3V USB-TTL的RX并共地，115200 / JustFloat；板载USB与无线共用USART1，不能从它读取本日志。

CH0门控状态（0释放等待、1空闲、2长按计时、3运行）；CH1请求百分比、CH2应用百分比、CH3电机编号、CH4物理输出编译开关、CH5链路、CH6/7有效/拒收包累计、CH8 UART错误累计。应用百分比不是实测转速或示波器占空比，LED1仅显示请求非零，LED2亮表示无线链路有效。

实机逐项记录：上电和按住KEY1上电不转；只有目标电机运行；松手/KEY2/F4/关遥控/3秒上限停转；恢复链路后不能自动转；复位、程序停喂狗和其他引脚电平/波形。软件测试通过不能替代这些物理检查，本台架的失联停止也不是空中失联降落策略。

## M3上电直通检查（明确请求后的独立入口）

`contest_motor_m3_direct` / `firmware/contest_motor_m3_direct.bin` 是用户要求的简单电路通断检查，只有M3 PC8在程序启动后持续输出HIGH；高有效N-MOS全导通，电机端有动力电压时立即运行。没有15%限幅、3秒截止、无线心跳或KEY1启动条件；不初始化无线、PWM或串口，JP3/JP4的LED控制保持关闭。其他旋翼PC6/7/9、PB6/7保持LOW，M5不参与。默认比赛入口仍不输出电机。

桨保持全部拆下，使用匹配电机的3.7V动力电压。USB只接控制部分时，若C+/C−没有动力电压，电机仍不会转。本文不保证未验收的双供电接法安全。用户已报告修复，修复和原故障原因尚无独立测量。

飞控KEY2按下后将M3锁存LOW，松开不会重新运行；按住KEY2上电也不启动。程序重新启动且KEY2松开会自动再次导通。Error_Handler和HardFault会写停止电平，但KEY2依赖软件轮询，无看门狗，程序卡死时不能保证按键有效；断开动力可停止。这里是持续全导通实物台架，不是飞行固件或自动停机演示。

## 四电机延时直通（当前用户要求）

`contest_motor_quad_direct` / `firmware/contest_motor_quad_direct.bin`：初始化后先保持旋翼全部LOW，等待2000ms，然后用同一次GPIOC BSRR写入将PC6/7/8/9全部HIGH，M1～M4持续全导通。不是PWM限幅或飞行控制，仍无无线/KEY1门控、3秒限时和LED供电输出。等待期间按过KEY2会取消本次启动；运行后按KEY2锁存全部LOW，释放不会重启。重启且KEY2未按会再次等待2秒自动导通。M6/M7保持LOW，M5不参与。只在程序启动时计时：若控制部分早已启动，后来才接动力电源，电机可能立即转动，不会从接入电池时重新等待2秒。全部拆桨，电机电压按DM22额定3.7V，供电故障修复/兼容性仍按实际核对。

## M4串口诊断

`contest_motor_quad_diag`保留启动后等2秒、四路持续全导通的行为。通过板载USB（USART1）和JP13（USART2）输出相同115200/8N1文本，每500ms一行；不是JustFloat。USB可直接接收，JP13需要独立兼容5V输入电平的TTL接收器：pin2 TXD2→接收器RX、pin4 GND→GND，不连两边VCC。USART1也接E49，所以调试文本可能进入模组；本程序不解析遥控。

`phase=WAIT/ON/STOP`为阶段，ON按四路ODR非零判定，不是M4通电证明。`PC9_cmd`为ODR输出锁存，`PC9_read`为IDR数字门限读回，`PC9_mode`为CRH输出模式，`PC9_cnf`为CRH配置。正常M4请求ON时应cmd=1、read=1、mode=2、cnf=0；停止应cmd=0/read通常0。这不能测量准确电压、电流、MOS管栅极/漏极电压或电机转速。cmd=1但read=0时查输出负载、短路或引脚异常；两者1但电机端0V时进一步量C+对GND、M4+对GND和M4−对GND，并检查驱动及供电路径，不能直接断言MOS损坏。

两路日志发送各有25ms超时；正常SysTick下软件轮询停止响应可能延迟约50ms，短按可能漏检。KEY2应按住直至电机停止，断开动力为物理停机。故障定位需要真实日志与电压读数，源码/编译不能代替实际运行。
