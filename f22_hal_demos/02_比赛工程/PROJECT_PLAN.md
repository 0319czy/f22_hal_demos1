## 1. 目标与比赛要求

按当前工程的悬停组目标推进：飞机放在地面红色中心区，一键起飞，自主稳定悬停，一键降落回中心附近。巡航组是不同任务，暂不纳入本计划；需要巡航时另加自主导航和环形区域定位阶段。

依据本工程保存的[比赛实施方案 2026.7](docs/references/比赛实施方案_2026.7.pdf)，飞行巡航定点赛 V5.0，PDF 第9～13页。以下是该文件要求；本地文件不能确认后续赛事通知是否修改规则。

| 条款 / PDF页 | 比赛要求 | 我们的实现和验收 |
|---|---|---|
| 赛项说明 / 9 | 4轴或6轴；每队1～3人，可制作1～3台，取最好成绩 | 当前一架四轴，使用M1/M2/M3/M6 |
| 2.3 / 10 | 悬停组从中心环红色圆形区起飞，朝向不限 | 在红圈内选定落地起飞点，机体坐标定义固定，不依赖地图朝向 |
| 2.4、2.11、6.8 / 10、13 | 无线一键起飞；起飞后自主控制，仅起降可遥控 | 起降键是项目映射；最后确认旧版F2起飞/F3降落/F4急停；用户希望F4降落，需发送/接收端成对实现，单端换键候选已撤回；不引入方向/油门遥控 |
| 2.7 / 10 | 悬停高度20～100cm，保持5秒以上不掉落、不跑飞，再一键降落 | 计划首个任务目标为40cm、稳定至少6秒；40cm/6秒是项目目标，不是新增比赛规则 |
| 2.9、3.4 / 10、12 | 飞行过程无时间限制，排名不计用时 | 达标后继续保持，等待降落键；不以运行5秒为自动降落条件 |
| 2.10、3.1 / 10、11 | 中心红圈500分；第n环为500−20n分，19环120分 | 控制落点漂移，记录机身中心实际落环；有光流不等于能识别红圈 |
| 2.8、3.2 / 10、11 | 标记机身中心；中心与环对应关系可直接看清加20分 | 制作不遮挡的中心标记，完整记录落点 |

| 1.1～1.2、4 / 9、12 | 自带合规1.6m×2.4m哑光布/灯布地图 | 准备实际地图，最后在同一材质和光照下验收 |
| 6.1～6.7 / 12 | 受保护电池；原厂动力和控制器；扩展传感器允许；桨叶不作限制但须安全 | 核对电池保护、F22及动力型号；不能仅凭能转判定器材合规 |
| 7.1 / 13 | 观众距地图至少2m | 赛前按场地要求布置 |

比赛只规定任务与器材。历史飞行配置的8°启动角、12cm起始测距、90%PWM试验上限和2秒离地超时，以及新系绳候选的90%单路上限/3秒离地超时，都是开发参数，不是比赛规则。此前拆桨差速台架另用15%基础需求、20%单路上限，不使用测距门限或离地超时。9～10cm垫高只用于历史高度环台架，正常起飞流程必须支持放在地面启动。

## 6. 代码管理与更新约定

- `src/main.c`负责协调；`src/flight/`放控制、状态机和协议；`src/hal/`放板级接口；`src/sensors/`放模块驱动；`src/bench/`仅放显式选择的诊断例程。
- `remote/tle100/`是遥控器独立工程；正式手动配置为`tle100_latency_fast`，自动按键耐久配置只用于试验，不混入正常控制。
- `scripts/`放构建/验收/看串口工具；`tests/`放主机测试；`docs/references/`放规则及手册；`docs/validation/`放按日期组织的真实证据。
- 飞行代码沿用`contest_aircraft1_radio_v2_jp13`遥控桥接；10月18日板上目标为`contest_tethered_flight_debug_jp13_pwm100`，具备真实PWM输出权限、1000‰上限、无光流闭环，尚未完成运行/飞行验收。默认`contest_hover`保留为无电机输出联调；构建/烧录始终写明环境，不混用台架与飞行参数。
- `firmware/`已有历史诊断固件以[固件索引](firmware/README.md)解释用途；当前烧入版必须对照hash和烧录记录，不凭文件名挑选。
- `archive/`是历史副本，不进入编译和当前文档校验。迁移保留旧目录全部内容；Downloads旧入口为指向本工程的软链接，不再是第二套开发代码。
- 每次改动更新本计划的状态、下一步、问题表，并将命令/实测/固件hash写入对应validation子目录。只在有证据时写“已完成”。
